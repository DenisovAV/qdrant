# Qdrant Edge — Dart & Flutter

On-device vector search for Dart and Flutter, powered by
[Qdrant Edge](https://qdrant.tech/documentation/edge/) — the Qdrant search
engine running **in-process**, no server and no network.

The SDK is a thin layer over the UniFFI binding generated from the shared
`qdrant-edge-ffi` Rust crate — the **same crate** the Swift and Kotlin SDKs bind,
so the three stay in lock-step by construction.

## Quick start

```dart
import 'package:qdrant_edge/qdrant_edge.dart';

final shard = EdgeShard.load(
  path: dir.path,
  config: EdgeConfig(
    vectorData: {'': VectorDataConfig(size: 4, distance: Distance.dot)},
  ),
);

shard.update(operation: UpdateOperation.upsertPoints(points: [
  Point(id: NumIdPointId(1), vector: SingleVector([1, 0, 0, 0])),
]));

final hits = shard.search(request: SearchRequest(
  query: NearestQuery(vector: DenseNamedVector([1, 0, 0, 0]), using: null),
  limit: 10,
));
```

See `example/` for a runnable demo and `test/` for a load → upsert → search
round-trip.

## How it works

- **Bindings.** `lib/src/qdrant_edge_ffi.dart` is generated by
  [`uniffi-bindgen-dart`](https://github.com/acterglobal/uniffi-dart) in library
  mode (it reads the UniFFI metadata embedded in the compiled cdylib; the crate
  uses `setup_scaffolding!()`, so there is no UDL). Regenerate with `./build.sh`
  after changing the FFI crate. `uniffi.toml` pins the Dart package name so the
  generated `@Native` asset ids resolve.
- **Native library.** The engine is delivered as a
  [Native Asset](https://dart.dev/interop/c-interop#native-assets): `dart test`,
  `dart run`, and `flutter test`/`flutter run` invoke `hook/build.dart`
  automatically — no `--enable-experiment` flag on Dart 3.12+.

## Distribution

`hook/build.dart` here is the **monorepo/development** hook: it builds the cdylib
from source, so it needs the nightly Rust toolchain and protobuf (see the
workspace README). A pub.dev release swaps it for a **prebuilt-download** hook
that fetches per-platform cdylibs from a GitHub release — the same shape the
Kotlin AAR and Swift XCFramework releases use. That release step is follow-up
work.

## Versioning

The version tracks `lib/edge/VERSION` (the published Qdrant Edge line) — the same
single source the Swift `edge-v$VERSION` tag and the Kotlin `VERSION_NAME` use.
